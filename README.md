# EcoLogger Analysis

自作の車載データロガー（EcoLogger）の走行を解析するデスクトップアプリ（Windows）。0.1.0：走行を開く・周の重ね合わせ・コース図・動画・計算チャンネル・配る形（exe）まで。

## めざすもの

- 周の重ね合わせ（横軸は時間・距離で切り替え）と、基準の周とのタイムの差
- コース図とカーソル（図を押すと、グラフも動画もその位置へ）
- カーソルに合わせて動く動画。2周の動画を同じ距離（同じ時間）で並べて比べる。**動画の位置はロガーが残す「動画の秒と測位の時刻の対応表」から出し、手で合わせない**。線を切り直すと、動画の位置もその場で新しい周の頭に合わせ直す。動画で線を確かめるときは、白線がボンネットに隠れた所でなく、そこから約14m先が線の上（SUGO 11/8で、カメラが線の真上を通るのは測位で越えた時刻の約0.1秒前と測った）
- 計算チャンネル（式を入れて新しいチャンネルを作る）

ロガーとの境目は、走行1回ぶんのファイルの形式だけ（物理量の表・周・動画の対応表・コースの線）。形式は [docs/format.md](docs/format.md)（ecorun、版1）。

## 使う人へ（配る形）

1. [Releases](https://github.com/ntakao2006-web/ecologger-analysis/releases) から `EcoLogger-Analysis-<版>-win64.zip` を落として広げる。EcoLogger アプリ（ロガーのPCの道具）から開くなら、
   `%USERPROFILE%\.ecologger\` に広げる（`%USERPROFILE%\.ecologger\EcoLogger-Analysis\EcoLogger-Analysis.exe` になる）
2. `EcoLogger-Analysis.exe` を開く。走行のフォルダー（`.ecorun`）を exe に落とすか、引数に渡しても開く
- **もう開いているときに別の走行を渡すと、開いている窓のほうで開いて前に出る**（窓は増えない）。
  EcoLogger アプリの「走行を見る」の「解析で開く」も、この形で走行を渡す
- 表示は Windows に入っている Microsoft Edge WebView2 ランタイムを使う。**無い機器では、いつものブラウザで開く**
  （画面の上に理由が出る。タブを閉じるとしばらくして終わる）。入れたいときは Microsoft の「Evergreen Bootstrapper」から
- 残すもの（最近開いた走行・線の版・計算チャンネル・読んだ表の控え）は `%USERPROFILE%\.ecologger-analysis\`

## 配る形を作る

```
python tools/build_exe.py           exe のフォルダーと zip を dist/ に作る（1分ほど。初めは .venv-build を作る）
python tools/build_exe.py --check   作った exe が起きて画面を返すかだけ確かめる
```

- 1つのファイルにまとめる形（`--onefile`）にせず、フォルダーの形を zip で配る（起動が速く、ウイルス対策に止められにくい）
- 版は `ecoanalysis/__init__.py` の `__version__`。zip の名前に入る

## 動かし方（開発）

```
python -m venv .venv
.venv\Scripts\python -m pip install -r requirements.txt
.venv\Scripts\python -m ecoanalysis
```

- 専用の窓で開く（pywebview。表示はWindowsに入っている Microsoft Edge WebView2 ランタイム）
- `--browser` を付けると、いつものブラウザで開く（開発用。WebView2 が無いときはこちらに自動で切り替わる）。`--port` で待つ番号を決められる
- 枠（周の表・グラフ・動画・コース図）は重ならず、隙間もできない。間の仕切りをドラッグして大きさを変え（細く寄せきると畳む。ダブルクリックで両隣を同じ大きさに、周の表の隣なら表がちょうど収まる幅に）、**枠の見出しをドラッグして、ほかの枠の上下左右の端へ落とすとそこへ動く**（真ん中なら入れ替え、画面の外周ならその辺いっぱい）。枠の ⤢ か見出しのダブルクリックでその枠だけを大きく出し、Esc で戻る。上の「配置」で決まった並べ方も選べ、手で変えた並びは次も同じ
- コース図の「航空写真」で、国土地理院の航空写真（全国最新写真（シームレス））を下に敷く。初めて見る所だけネットが要り、取った写真は `~/.ecologger-analysis/tiles/` に残るので、一度見たコースはネットが無くても出る。出典は図の右下に出す
- 「走行を開く…」で走行のフォルダー（`.ecorun`）を選ぶ。選ぶ窓は、前回開いた走行のあるフォルダーから始まる。別の日の走行も続けて開ける。最近開いたものは上の一覧から開ける
- 前回の続きがあるときは、ボタンが「続きから：<走行の名前>」と「別の走行…」の2つに分かれる。「続きから」で、前回開いていた走行を開き直し、選んでいた周を選ぶ（開いている走行と選んでいる周は `~/.ecologger-analysis/last.json` に覚える。全部閉じても前の分は残る）
- 周の表は「コースの線で切った周」（ふだん）と「ロガーの数え」を切り替えられる。ベストとの差は、同じコースの開いている走行どうしで比べる
- 周の表で周を選ぶ（8周まで）と、グラフに重ねて出す。横軸は距離と時間を切り替えられ、2周以上なら基準の周（ふだんは一番速い周）とのタイムの差も出す。ホイールで拡大、ドラッグで移動、ダブルクリックで全体
- コース図に選んだ周の走った線と、コントロールライン・セクターの線を描く。グラフのカーソルの位置に車の印（走る向きを指す矢じり。印の●・○と見分けられる形）が出て、図を押すとグラフのカーソルがその場所へ動く。車の印はつかんで線に沿って引ける（グラフ・動画のカーソルも動く）。「車を追う」をオンにすると、車をいつも図の真ん中に出す（倍率はそのまま。全体を見ているときだけ少し寄る）。図を手で引くか、ダブルクリックで全体に戻すと外れる。追っているときに図を押すと、押した所が車から離れている分（図の上の距離）だけ、基準の周の線に沿ってカーソルを先へ送る（デジスパイスの送り方。遠くを押せば次の区間へ大きく、車のすぐ横をかちかち押せば少しずつ。押す向きは関係ない。Shift を押しながらだと手前へ戻る。周の端で止まる）
- コース図の「コース図」で、道路の両側の縁を薄く描く（周の線がコース幅のどこを通ったかを読むため）。縁は国土地理院の地図（地理院地図Vectorの道路縁）と航空写真から自動で作り（初めてのコースだけネットが要る。数秒〜十数秒）、コースごとに `~/.ecologger-analysis/outlines/` に残す。地図の線がコースの中を通る所（合流車線の境目など）は、走行の全部の測位が横へ散らばった幅で見分けて捨てる。ピットロードは、ピットに入って出た通過の測位から作って足す（コースの縁の外を通ってコースへ戻った続きのうち、コースを出た所・戻った所がいちばん多く重なるものをピットの通過とし、通った回を重ねて入口から出口まで通った所だけを通る道を案内にして、回の線を縦の位置でそろえた横の位置の中央値を中心線にする。ガレージへの寄り道は入れない。左右の縁は、中心線から航空写真の舗装の切れ目までを幅にし、写真の境目へ吸い付かせてならす。コースの縁と重なる所は描かない。ピットを通った回が2回より少なければ作らない）。引いて見てコースの幅が数画素になるときは、縁を太らせて道の帯にする（縁が周の線の下に隠れないように）
- ゼブラ（赤白の縁石）は航空写真から「ある区間」だけを拾い（縁の近くで、白と赤みが走る向きに交互に並ぶ所。途切れない白線は拾わない。10 mまでの途切れはつなぎ、12 mより短いものは捨てる）、縁に沿った幅1 mの帯を走る向きに1 mおきの赤白で描く。ゼブラのある所は、縁をゼブラの内側の端（舗装と縁石の境目）へ寄せ、帯はその外に置く（地図の道路縁は縁石の外の端に引かれていることが多く、そのままだと帯が道の中に食い込む）。細く見えるときも4画素より細くしない。コーナーの手前の距離の看板は写真では見分けられないので描かない
- 「コース図を直す」で、自動で作ったコース図を手で直す（自動では決めきれない所：写真で色の薄い縁石・合流の境目など）。道具は、点を動かす（なめらかさの距離の内の点も、離れるほど少しずつ一緒に動く）・なめらかにする（同じ線の2か所のあいだの細かいガタガタを、カーブの形は残してならす。同じ所を2回押すと線1本まるごと。ならす幅はなめらかさの半分で、押し直すほどなめらかになる）・まっすぐにする（同じ線の2か所のあいだ）・消す・つなぐ（線の端どうし。開いた線の端は橙の点で出る）・ゼブラを足す（縁の2か所のあいだの外側に。外側は走った線から離れる向き。両端は「端の細り」の長さで尖る）・ゼブラを消す・看板（コーナーの手前の「100」などの距離の看板を置く・押すと消す）・なぞる（縁をマウスでざっとなぞると、裏が近くの縁へ吸い付いた線にする。航空写真の色が変わる所・路面が切れる所・白線と、地図の道路縁を候補にし、なぞった線から横へ「画面の24画素」の幅で探す（寄るほど細かく）。前後の点で横に跳ばないようにまとめて選び、縁が見つからない所はなぞったまま。なぞり始めと終わりの30画素の内に同じ縁があれば、そのあいだを置き換え（輪の縁は、なぞった長さに近いほうのあいだ。ゼブラは載り直す）、無ければ新しい線として足す。キーの 9 でも選べる。右ボタンの8つの向きには入れていない）・線の種類（線を押すと、「種類」の欄で選んだもの＝コースの縁・ピットロード・その他の舗装にする。キーの 0）。「ピットロードを足す」で、いま直しているコースの縁の外を通ったピットの通過から、ピットロードの縁を作って足す（自動のコース図と同じ作り方。十数秒かかる。前からあるピットロードの線は、置き換えるか残すかを聞く。ひとつ戻すで戻せる）。サーキットの舗装の全部（ピットロード・使っていないシケイン・ショートコース・エスケープゾーン）を1枚のコース図に描き、走ったレイアウトはコントロールラインの版で分ける。ピットロードは破線（写真の上では黄色）、その他の舗装は点線で細く描き、引いて見たときの道の帯にはしない。なぞるで足す線は「種類」の欄の種類になる（ピットロード・その他の舗装では、どちら側がコースかを決めずに境目を探す）。種類は直したコース図のファイルに線と同じ順の `kinds` で残す（無い前のファイルは全部コースの縁）。ゼブラは縁にくっついていて（内側の端が縁の上、幅は点ごと）、縁を動かす・なめらかにする・まっすぐにすると一緒に動く。点を動かすでゼブラの外側の端をつかむと幅が変わり（なめらかさの距離の内も少しずつ）、両端の四角をつかむと縁に沿って伸び縮みする（端の細りは端と一緒に動き、伸ばした所は手前の幅で埋める）。消すでゼブラの一部を抜ける。前に保存した決まった幅のゼブラも読み、縁に載せ直す。道具は、図の上で右ボタンを押したまま8つの向きのどれかへ引いても切り替わる（引き始めると押した所のまわりに8つの道具が出る。上＝点を動かす・右上＝なめらかに・右＝まっすぐ・右下＝つなぐ・下＝消す・左下＝ゼブラを足す・左＝ゼブラを消す・左上＝看板。ボタンの並びと同じで、1〜8 のキーでもよい。短く押して離すと、2か所押す道具の押しかけを取り消す）。Ctrl+Z か「ひとつ戻す」で戻し、Ctrl+Y（Ctrl+Shift+Z）か「やり直す」で戻した分をやり直す。Esc で押しかけを取り消す。「保存」か Ctrl+S で、直したものがコースごとに `~/.ecologger-analysis/outlines/edit-*.json` に残り、自動のものより先に出る（自動の作り方の版が上がっても残る）。「自動に戻す」で消せる
- コース図の「塗る」で線の色を選ぶ：周の色（ふだん）／値（基準の周の線を、選んだチャンネルで青の濃さに）／タイムの差の増え方・タイムの差（比べる周＝基準の次に選んだ周の線を、得は青・損は赤に）。色の段はその周の中の 2〜98% で、「範囲」に数を入れると固定できる。左下に凡例、線に当てるとその所の値・タイムの差・測位の精度が出る。測位の質が悪い所（精度 1.5 m より悪い・0.3秒より抜けた）は細いグレー
- 「減速を点線」で前後Gが −0.1 G より小さい所を点線に、「測位の精度」で点ごとの精度の円を、「印」で周ごとのブレーキの踏み始め▼・離した所▲（前後Gから）と、選んだチャンネル（ふだん車速）のいちばん低い所●・高い所○を描く。数は近づけると出る
- 周の表の下に、同じコースの開いている走行から出した理論ベスト（区間・セクター）・連続ベスト（周の境目をまたいで続けて走った区間を1周ぶんつないだ最速）・平均の周（区間ごとの平均の和。区間タイムがその区間の中央値より5%以上遅い周は、その区間だけ外す）を出す（測位の抜けた周は使わない）
- 「区間を自動で置く」で、基準の周のブレーキの踏み始め（ブレーキのチャンネルがあればそれ、無ければ前後G。どちらも無ければ直線の最高速の所）に区間（コーナー）の線を置き、同じコースの全部の周をその線で切る（周ごとに切らず、全部の周に同じ線）。線はコースごとに、使っている線の版に（版を使っていなければ、その場で置いた分として）`lines.json` に残り、コース図に「区2」などの札つきの細い破線で出る。周の表の下の「区間」の表に、選んだ周（基準の周を先に4周まで）の区間ごとのタイム・ベストとの差・入口の速さ・ブレーキの踏み始め（区間の線から m、＋は奥）・ボトムの速さと位置・ボトムの前後2秒の最小の旋回半径（測位から）・出口の速さと、区間ごとのベスト・平均・ばらつきを出す。紫はその区間のベスト、緑・赤は基準の周より速い・遅い
- 区間の表の行を押すと、地図をその区間に寄せ（車を追うのは外れる）、グラフの横の範囲をその区間（前後に少し余らせる）にし、カーソル・動画を区間の頭へ動かす。ブレーキの数（点線の下線）を押すと、基準の周と押した周（基準の周の行なら2番目の周）の動画を、それぞれのブレーキの踏み始めの瞬間で止めて並べる（カーソルを動かすと、いつもの「同じ所」に戻る）。グラフの「区間の頭で差を0に」で、基準の周との差を区間ごとにその頭で0から描く。グラフを拡大している（Shift＋ドラッグで範囲に寄れる）ときは、差の段の見出しに、見ている範囲の頭から終わりまでのタイムの差を周ごとに出す（0にしていない差で）
- 「区間を直す」で、区間の線を手で直す：グラフ・地図・動画でカーソルを動かして「カーソルの所で切る」で線を足し（その区間を2つに分ける）、地図の線をつかんで基準の周の線に沿って引くと動き（押すと選ぶ）、「選んだ線をカーソルの所へ」「選んだ線を消す」（Delete キーでも。前後の区間を1つにつなぐ）・区間ごとの「前とつなぐ」、区間に名前（「1コーナー」など。表と地図の札に出る）を付けられる。ほかの線・コントロールラインから10 mの内には足さない。「保存」（Ctrl+S）で線の版（版を使っていなければその場で置いた分）に線と名前（`split_names`）を残し、同じコースの全部の周を切り直す。区間の線はグラフにも縦の破線で出る。「区間を置き直す」（自動）をすると名前は消える
- 「線を直す」で、コントロールライン・セクターの線を図の上で置き直し、名前をつけて残せる（ロガーの線と解析の線が違うとき用）。書き出しの線（ロガーと同じ）へはいつでも戻せる
- 読んだ表は `~/.ecologger-analysis/cache/` に覚え、2回目からはすぐ開く（初回は決勝2時間半ぶんで数秒）
- 試験：`.venv\Scripts\python -m unittest discover -s tests`
- 作りものの走行データ：`.venv\Scripts\python -m ecoanalysis.sample data\sample.ecorun`（本物の記録が無いときの画面づくり用。`data/` はGitに入れない）

## 作り

- `ecoanalysis/server.py`：画面と裏の処理をつなぐローカルのHTTPサーバー（127.0.0.1だけで待つ）。動画は `/media/` から、開いている走行の動画だけを途中から読める形（Range、一度に8MBまで）で渡す
- `ecoanalysis/app.py`：入口。サーバーを立てて pywebview の窓で開く。WebView2 が無ければブラウザで開き、画面からの知らせ（3秒ごと）が途絶えたら終わる。開いている間は `~/.ecologger-analysis/running.json` に番号を置き、2つ目の起動は走行をそちらへ渡して（`/api/handover`）終わる。画面は `rev` が変わったのを見て一覧を読み直す
- `tools/build_exe.py`・`tools/exe_main.py`：配る形（PyInstaller）
- `ecoanalysis/session.py`：走行データ（ecorun）を読み、形が決まりどおりかを確かめる
- `ecoanalysis/laps.py`：コースの線で、測位から周を切り直す（線を越えた時刻＝線の手前と先の2点から補った値）。ロガーが数えた周と並べて出す
- `ecoanalysis/overlay.py`：選んだ周を重ねる。距離は基準の周の走った線に沿った距離で、ほかの周は測位の点を基準の線へ投影して合わせる（同じ場所どうしが並び、タイムの差は「同じ場所に何秒遅れて着いたか」）
- `ecoanalysis/lines.py`：コースの線の版（名前つき）を `~/.ecologger-analysis/lines.json` に残す。版を使うと、同じコースの走行は全部その線で周を切り直す。区間の線（splits）も版ごとに持つ
- `ecoanalysis/sections.py`：区間（コーナー）の線を基準の周のブレーキの踏み始めに置く・周ごとの区間の数（入口・ブレーキ・ボトム・半径・出口）・連続ベスト・同じコースの理論ベストと平均の周
- `ecoanalysis/dynamics.py`：測位から計算する横G（右へ曲がると＋）・前後G・旋回半径。位置を0.5秒でならして2回微分する（前後Gは受信機の速さの微分）。測位が0.25秒より粗い記録では作らない
- `ecoanalysis/formula.py`：計算チャンネル。式（四則・比較・論理・if・関数・積分・変化率・平均）を自前で字句に分けて木にし、自前で計算する（Pythonの`eval`は使わない）。残し場所は `~/.ecologger-analysis/channels.json`。重ね合わせでは周ごとに計算する（積分は周の頭で0から）
- `ecoanalysis/sample.py`：作りものの走行データを書く
- `web/`：画面（HTML・CSS・JavaScript）。グラフとコース図は自前の canvas（`web/chart.js`・`web/map.js`）で、外のライブラリを使わない
- `web/outedit.js`：コース図のエディタ（中身と道具だけ。描き方とマウスは `web/map.js` が受け持つ）
- `web/layout.js`：枠の並び。「左右に割る・上下に割る」の入れ子の木で持ち、仕切りのドラッグ・見出しのドラッグで動かす・畳む・1つの枠を大きく出す・配置の記憶。動画の枠が横長なら2本を左右に並べる
- `ecoanalysis/outline.py`・`ecoanalysis/mvt.py`：コース図（道路の縁）。案内の周の線から2 mおきに横断面を切り、地図の道路縁（ベクトルタイルを自前で読む）に当たればその距離、無ければ航空写真の色で舗装の切れ目を探す。走った幅より内側の線は縁にしない。1回目の縁からコースの真ん中の線を出し、2回目は真ん中から半分の幅の近くだけを探して測り直す（走行ラインが縁に触れる所・別の道の縁を拾う所で線が切れたり、ひげが出たりしないように）。脇道との合流で縁が曲がり込むこぶ（前後100 mの中央値から0.5 m以上飛び出す所）は削り、70 mまでの抜けは補う。同じコースで開いている走行は全部まとめて使う（周が多いほど、コースの中の線を見分けやすい）。手で直したコース図（縁・ゼブラ・距離の看板）は別のファイルにコースごとに残し（`/api/outline/save`・`/api/outline/reset`）、あればそちらを出す。エディタでなぞった線は `/api/outline/snap` で縁へ吸い付かせる（`Outlines.snap`。走行の中身は使わない）
- `ecoanalysis/tiles.py`：航空写真のタイル。画面は `/tiles/gsi/{z}/{x}/{y}.jpg` を裏から読み、裏は手元に無ければ国土地理院から取って残す（送るのはタイルの番号だけ。つながらないときは30秒取りに行かない）
- `web/video.js`：動画。2周を上下に並べ、止まっているときはカーソルの所へ2本とも動かす。再生すると上の動画からカーソルを動かし、下の動画は同じ所（距離の横軸なら同じ地点）を速さを少し変えて追う。動画の秒は書き出しの対応表（sync）から補って出す

画面とPythonのやりとりは `/api/` のHTTPだけにしてあり、pywebview 独自の呼び出しは使わない。あとで Electron や Tauri へ移すときも、画面をそのまま使える。
