# EcoLogger Analysis

自作の車載データロガー（EcoLogger）の走行を解析するデスクトップアプリ（Windows）。0.1.0：走行を開く・周の重ね合わせ・コース図・動画・計算チャンネル・配る形（exe）まで。

## めざすもの

- 周の重ね合わせ（横軸は時間・距離で切り替え）と、基準の周とのタイムの差
- コース図とカーソル（図を押すと、グラフも動画もその位置へ）
- カーソルに合わせて動く動画。2周の動画を同じ距離（同じ時間）で並べて比べる。**動画の位置はロガーが残す「動画の秒と測位の時刻の対応表」から出し、手で合わせない**
- 計算チャンネル（式を入れて新しいチャンネルを作る）

ロガーとの境目は、走行1回ぶんのファイルの形式だけ（物理量の表・周・動画の対応表・コースの線）。形式は [docs/format.md](docs/format.md)（ecorun、版1）。

## 使う人へ（配る形）

1. [Releases](https://github.com/ntakao2006-web/ecologger-analysis/releases) から `EcoLogger-Analysis-<版>-win64.zip` を落として広げる。EcoLogger アプリ（ロガーのPCの道具）から開くなら、
   `%USERPROFILE%\.ecologger\` に広げる（`%USERPROFILE%\.ecologger\EcoLogger-Analysis\EcoLogger-Analysis.exe` になる）
2. `EcoLogger-Analysis.exe` を開く。走行のフォルダー（`.ecorun`）を exe に落とすか、引数に渡しても開く
- **もう開いているときに別の走行を渡すと、開いている窓のほうで開いて前に出る**（窓は増えない）。
  EcoLogger アプリの「走行を見る」の「解析で開く」も、この形で走行を渡す
- 表示は Windows に入っている Microsoft Edge WebView2 ランタイムを使う。**無い機器では、いつものブラウザで開く**
  （画面の上に理由が出る。タブを閉じるとしばらくして終わる）。入れたいときは Microsoft の「Evergreen Bootstrapper」から
- 残すもの（最近開いた走行・線の版・計算チャンネル・読んだ表の控え）は `%USERPROFILE%\.ecologger-analysis\`

## 配る形を作る

```
python tools/build_exe.py           exe のフォルダーと zip を dist/ に作る（1分ほど。初めは .venv-build を作る）
python tools/build_exe.py --check   作った exe が起きて画面を返すかだけ確かめる
```

- 1つのファイルにまとめる形（`--onefile`）にせず、フォルダーの形を zip で配る（起動が速く、ウイルス対策に止められにくい）
- 版は `ecoanalysis/__init__.py` の `__version__`。zip の名前に入る

## 動かし方（開発）

```
python -m venv .venv
.venv\Scripts\python -m pip install -r requirements.txt
.venv\Scripts\python -m ecoanalysis
```

- 専用の窓で開く（pywebview。表示はWindowsに入っている Microsoft Edge WebView2 ランタイム）
- `--browser` を付けると、いつものブラウザで開く（開発用。WebView2 が無いときはこちらに自動で切り替わる）。`--port` で待つ番号を決められる
- 枠（周の表・グラフ・動画・コース図）は重ならず、隙間もできない。間の仕切りをドラッグして大きさを変え（細く寄せきると畳む。ダブルクリックで両隣を同じ大きさに、周の表の隣なら表がちょうど収まる幅に）、**枠の見出しをドラッグして、ほかの枠の上下左右の端へ落とすとそこへ動く**（真ん中なら入れ替え、画面の外周ならその辺いっぱい）。枠の ⤢ か見出しのダブルクリックでその枠だけを大きく出し、Esc で戻る。上の「配置」で決まった並べ方も選べ、手で変えた並びは次も同じ
- コース図の「航空写真」で、国土地理院の航空写真（全国最新写真（シームレス））を下に敷く。初めて見る所だけネットが要り、取った写真は `~/.ecologger-analysis/tiles/` に残るので、一度見たコースはネットが無くても出る。出典は図の右下に出す
- 「走行を開く…」で走行のフォルダー（`.ecorun`）を選ぶ。別の日の走行も続けて開ける。最近開いたものは上の一覧から開ける
- 周の表は「コースの線で切った周」（ふだん）と「ロガーの数え」を切り替えられる。ベストとの差は、同じコースの開いている走行どうしで比べる
- 周の表で周を選ぶ（8周まで）と、グラフに重ねて出す。横軸は距離と時間を切り替えられ、2周以上なら基準の周（ふだんは一番速い周）とのタイムの差も出す。ホイールで拡大、ドラッグで移動、ダブルクリックで全体
- コース図に選んだ周の走った線と、コントロールライン・セクターの線を描く。グラフのカーソルの位置に点が出て、図を押すとグラフのカーソルがその場所へ動く
- コース図の「コース図」で、道路の両側の縁を薄く描く（周の線がコース幅のどこを通ったかを読むため）。縁は国土地理院の地図（地理院地図Vectorの道路縁）と航空写真から自動で作り（初めてのコースだけネットが要る。数秒〜十数秒）、コースごとに `~/.ecologger-analysis/outlines/` に残す。地図の線がコースの中を通る所（合流車線の境目など）は、走行の全部の測位が横へ散らばった幅で見分けて捨てる。ピットロードは描かない。引いて見てコースの幅が数画素になるときは、縁を太らせて道の帯にする（縁が周の線の下に隠れないように）
- ゼブラ（赤白の縁石）は航空写真から「ある区間」だけを拾い（縁の近くで、白と赤みが走る向きに交互に並ぶ所。途切れない白線は拾わない。10 mまでの途切れはつなぎ、12 mより短いものは捨てる）、縁に沿った幅1 mの帯を走る向きに1 mおきの赤白で描く。ゼブラのある所は、縁をゼブラの内側の端（舗装と縁石の境目）へ寄せ、帯はその外に置く（地図の道路縁は縁石の外の端に引かれていることが多く、そのままだと帯が道の中に食い込む）。細く見えるときも4画素より細くしない。コーナーの手前の距離の看板は写真では見分けられないので描かない
- コース図の「塗る」で線の色を選ぶ：周の色（ふだん）／値（基準の周の線を、選んだチャンネルで青の濃さに）／タイムの差の増え方・タイムの差（比べる周＝基準の次に選んだ周の線を、得は青・損は赤に）。色の段はその周の中の 2〜98% で、「範囲」に数を入れると固定できる。左下に凡例、線に当てるとその所の値・タイムの差・測位の精度が出る。測位の質が悪い所（精度 1.5 m より悪い・0.3秒より抜けた）は細いグレー
- 「減速を点線」で前後Gが −0.1 G より小さい所を点線に、「測位の精度」で点ごとの精度の円を、「印」で周ごとのブレーキの踏み始め▼・離した所▲（前後Gから）と、選んだチャンネル（ふだん車速）のいちばん低い所●・高い所○を描く。数は近づけると出る
- 「線を直す」で、コントロールライン・セクターの線を図の上で置き直し、名前をつけて残せる（ロガーの線と解析の線が違うとき用）。書き出しの線（ロガーと同じ）へはいつでも戻せる
- 読んだ表は `~/.ecologger-analysis/cache/` に覚え、2回目からはすぐ開く（初回は決勝2時間半ぶんで数秒）
- 試験：`.venv\Scripts\python -m unittest discover -s tests`
- 作りものの走行データ：`.venv\Scripts\python -m ecoanalysis.sample data\sample.ecorun`（本物の記録が無いときの画面づくり用。`data/` はGitに入れない）

## 作り

- `ecoanalysis/server.py`：画面と裏の処理をつなぐローカルのHTTPサーバー（127.0.0.1だけで待つ）。動画は `/media/` から、開いている走行の動画だけを途中から読める形（Range、一度に8MBまで）で渡す
- `ecoanalysis/app.py`：入口。サーバーを立てて pywebview の窓で開く。WebView2 が無ければブラウザで開き、画面からの知らせ（3秒ごと）が途絶えたら終わる。開いている間は `~/.ecologger-analysis/running.json` に番号を置き、2つ目の起動は走行をそちらへ渡して（`/api/handover`）終わる。画面は `rev` が変わったのを見て一覧を読み直す
- `tools/build_exe.py`・`tools/exe_main.py`：配る形（PyInstaller）
- `ecoanalysis/session.py`：走行データ（ecorun）を読み、形が決まりどおりかを確かめる
- `ecoanalysis/laps.py`：コースの線で、測位から周を切り直す（線を越えた時刻＝線の手前と先の2点から補った値）。ロガーが数えた周と並べて出す
- `ecoanalysis/overlay.py`：選んだ周を重ねる。距離は基準の周の走った線に沿った距離で、ほかの周は測位の点を基準の線へ投影して合わせる（同じ場所どうしが並び、タイムの差は「同じ場所に何秒遅れて着いたか」）
- `ecoanalysis/lines.py`：コースの線の版（名前つき）を `~/.ecologger-analysis/lines.json` に残す。版を使うと、同じコースの走行は全部その線で周を切り直す
- `ecoanalysis/formula.py`：計算チャンネル。式（四則・比較・論理・if・関数・積分・変化率・平均）を自前で字句に分けて木にし、自前で計算する（Pythonの`eval`は使わない）。残し場所は `~/.ecologger-analysis/channels.json`。重ね合わせでは周ごとに計算する（積分は周の頭で0から）
- `ecoanalysis/sample.py`：作りものの走行データを書く
- `web/`：画面（HTML・CSS・JavaScript）。グラフとコース図は自前の canvas（`web/chart.js`・`web/map.js`）で、外のライブラリを使わない
- `web/layout.js`：枠の並び。「左右に割る・上下に割る」の入れ子の木で持ち、仕切りのドラッグ・見出しのドラッグで動かす・畳む・1つの枠を大きく出す・配置の記憶。動画の枠が横長なら2本を左右に並べる
- `ecoanalysis/outline.py`・`ecoanalysis/mvt.py`：コース図（道路の縁）。案内の周の線から2 mおきに横断面を切り、地図の道路縁（ベクトルタイルを自前で読む）に当たればその距離、無ければ航空写真の色で舗装の切れ目を探す。走った幅より内側の線は縁にしない。1回目の縁からコースの真ん中の線を出し、2回目は真ん中から半分の幅の近くだけを探して測り直す（走行ラインが縁に触れる所・別の道の縁を拾う所で線が切れたり、ひげが出たりしないように）。脇道との合流で縁が曲がり込むこぶ（前後100 mの中央値から0.5 m以上飛び出す所）は削り、70 mまでの抜けは補う。同じコースで開いている走行は全部まとめて使う（周が多いほど、コースの中の線を見分けやすい）
- `ecoanalysis/tiles.py`：航空写真のタイル。画面は `/tiles/gsi/{z}/{x}/{y}.jpg` を裏から読み、裏は手元に無ければ国土地理院から取って残す（送るのはタイルの番号だけ。つながらないときは30秒取りに行かない）
- `web/video.js`：動画。2周を上下に並べ、止まっているときはカーソルの所へ2本とも動かす。再生すると上の動画からカーソルを動かし、下の動画は同じ所（距離の横軸なら同じ地点）を速さを少し変えて追う。動画の秒は書き出しの対応表（sync）から補って出す

画面とPythonのやりとりは `/api/` のHTTPだけにしてあり、pywebview 独自の呼び出しは使わない。あとで Electron や Tauri へ移すときも、画面をそのまま使える。
